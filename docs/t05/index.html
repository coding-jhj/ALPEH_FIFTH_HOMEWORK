대화가 끊겨도 이어지는 프로젝트

두 AI가 같은 검사 10개를 이어서 통과시킨 기록 · ALEPH T05 · 2026-09-01

한 줄 요약

마인크래프트 서버 정보판에 멀티 LLM 요약 브리핑 + 제공자 폴백 기능을 붙였다. 착수 전에 검사 10개와 사용 상한을 고정했고, AI A가 6/10에서 멈춘 뒤 AI B가 대화 전문 없이 인수인계 문서 한 장만으로 이어받아 10/10을 만들었다.

무엇을 만들었나

기존 정보판은 접속자 수를 mcstatus.io에서 가져오고, 실패하면 mcsrvstat.us로 갈아타고, 둘 다 실패하면 "데이터 안 옴"을 솔직히 표시했다. 한 곳만 믿지 않는다는 구조다.

이번 개선은 같은 발상을 LLM에 적용한다. 요약 3줄을 만들 때 gemini → groq → rule 순서로 시도하고, 앞이 실패하면 다음으로 넘어가고, 전부 실패하면 LLM 없이 계산만으로 3줄을 만든 뒤 화면에 요약 폴백: 규칙기반을 표시한다. AI가 전부 죽어도 카드는 비지 않는다.

새 폴더 재현 결과

인수인계 문서를 확정하기 전에, 저장소를 빈 폴더에 새로 clone해서 문서의 실행 명령만 그대로 따라갔다. npm ci → npm run verify:brief → 통과 6/10, 첫 실패 T05-T03이 그대로 재현됐다.

인수인계 누락 기록

누락 1건. 작업을 막지는 않았다. AI B가 스스로 발견했다.

문서의 BASE_COMMIT은 b6043fa(코드 커밋)인데, AI B가 clone한 시점의 저장소 HEAD는 38854f1이었다. 사이 두 커밋이 모두 문서 커밋이라 src/lib/brief.ts 코드는 동일했고 실행에는 영향이 없었다.

수정 전 BASE_COMMIT: b6043fa… → 수정 후 같은 값에 "코드 기준 커밋이며 인계 시점 HEAD는 38854f1"이라는 설명 추가. AI B가 실제로 받은 문서는 sha256 그대로 보존하고, 수정은 AI B 종료 뒤 별도 커밋으로 남겼다. 전문은 docs/t05-handoff-gaps.md에 있다.

다음 작업의 도구 선택 기준

검사가 먼저 고정돼 있으면 어느 모델이든 쓰고, 검사를 만드는 단계와 실패를 파고드는 단계에는 더 강한 모델을 쓴다.

짧은 확인 방법

① 어디로 가나요
이 페이지, 그리고 소스 저장소 github.com/coding-jhj/ALPEH_FIFTH_HOMEWORK

② 3단계 이내 무엇을 하나요
1) git clone https://github.com/coding-jhj/ALPEH_FIFTH_HOMEWORK.git
2) npm ci
3) npm run verify:brief

③ 무엇이 보이면 통과인가요
마지막 줄에 통과 10/10. 위 비교표의 AI A 6/10 · AI B 10/10과 일치. 커밋 4개가 A 시작 → A 종료 → B 시작 → B 종료 순서로 보임.

④ 안 될 때 무엇이 보이나요
통과 6/10과 첫 실패 검사: T05-T03이 보이면 AI B 커밋이 빠진 상태다 (git log -1이 f61552a인지 확인). Node 미설치면 npm: command not found, 설치 미완료면 Cannot find module '.../src/lib/brief'가 보인다.

AI와 나의 판단

① AI에게 맡긴 일
src/lib/brief.ts 구현(AI A 6개 · AI B 4개), 인수인계 문서 초안 작성, 고정 검사 10개의 코드화, 이 보고서 페이지 작성.

② 내가 직접 판단한 일
개선 주제 선정(멀티 LLM 폴백), 검사 10개와 기대값·경계값 확정, A/B 분할선을 6:4로 나눠 A가 10/10을 만들지 못하게 막은 것, 상한 120분/60회 결정, 인수인계 문서를 빈 폴더에서 실제 재현해 검증한 것, AI B의 10/10 보고를 믿지 않고 같은 명령을 직접 다시 돌려 확인한 것.

③ AI 제안을 따르지 않은 일
진행 보조 AI가 인수인계 문서의 마크다운 서식이 어긋난 것을 "AI A가 쓴 것으로 두고 손대지 말자"고 제안했으나 따르지 않았다. 서식만 고치고 수정 사실을 별도 커밋과 이 보고서에 명시하는 쪽을 택했다. 읽는 사람이 문서를 실제로 쓸 수 있는 것이 더 중요하고, 누가 무엇을 고쳤는지는 커밋으로 남기면 증거가 흐려지지 않는다고 판단했다.
